## Chatper4 大语言模型 2026/04/20
### 什么是 LLM
一般来说，LLM 指包含数百亿（或更多）参数的语言模型，它们往往在数 T token 语料上通过多卡分布式集群进行预训练，具备远超出传统预训练模型的文本理解与生成能力。广义的 LLM 一般覆盖了从十亿参数（如 Qwen-1.5B）到千亿参数（如 Grok-314B）的所有大型语言模型。只要模型展现出<strong>涌现能力</strong>，即在一系列复杂任务上表现出远超传统预训练模型（如 BERT、T5）的能力与潜力，都可以称之为 LLM。  
#### LLM的能力
1.涌现能力，即随着参数量的增大，量变产生质变，在不改变架构的基础上，模型涌现了小参数时不具备的能力。  
2.允许人类反馈强化学习，下游任务节约大量算力。  
3.指令遵循。通过使用自然语言描述的多任务数据进行微调，也就是指令微调。指令遵循能力意味我们不再需要每一件事都先教模型，然后它才能去做。我们只需要在指令微调阶段混合多种指令来训练其泛化能力，LLM 就可以处理人类绝大部分指令，即可以灵活地解决用户遇到的问题。  
4.逐步推理，即对需要多层推理，逻辑环绕问题的处理能力。  
#### LLM的特点
1.LLM 天生即具有多语言、跨语言能力。  
2.通过引入 Adapter 层和图像编码器，并针对性地在图文数据上进行有监督微调，模型能够具备不错的图文问答甚至生成能力。  
3.幻觉，是指 LLM 根据 Prompt 杜撰生成虚假、错误信息的表现。通过在Prompt里进行限制、RAG（检索增强生成）来指导生成等在一定程度减弱幻觉但无法彻底根除。  
### 如何训练一个 LLM
![example](/image/LLM训练的三个阶段.png)  
一般而言，训练一个完整的 LLM 需要经过图1中的三个阶段——Pretrain、SFT 和 RLHF。但我在第二章的qa中已经回答了这个问题，大体上是差不多的，这里只做简单的叙述。  
#### Pretrain
根据由 OpenAI 提出的 Scaling Law：C ~ 6ND，其中 C 为计算量，N 为模型参数，D 为训练的 token 数，可以实验得出训练 token 数应该是模型参数的 1.7倍，也就是说 175B 的 GPT-3，需要使用 300B token 进行预训练。而 LLaMA 更是进一步提出，使用 20倍 token 来训练模型能达到效果最优，因此 175B 的 GPT-3，可以使用3.5T token 数据预训练达到最优性能。  
分布式训练框架的核心思路是数据并行DP（Data Parallelism）和模型并行MP（Model Parallelism）。  
DP最基础的要求是<strong>训练模型的尺寸可以被单个GPU显存容纳</strong>，但是由于增大训练的 batch_size 会增大显存开销，无法使用较大的 batch_size 进行训练；同时，训练数据量非常大，使用单张 GPU 训练时长难以接受。那么就把数据分在不同的GPU上，把global batch被拆成多个local batch，每个GPU独立前向计算/反向传播得到各自的梯度，此时数据不同导致每个模型的梯度不同，使用AllReduce同步梯度，传统的是将所有的梯度求和再求平均（这是由于梯度是对损失函数求导，而导数也具备线性相加的特性），然后再分给每个GPU，这种方式造成了巨大的通信带宽压力。  
因此现在主流使用ring allreduce，该方式将n个GPU视作一个环，每个GPU只接受相邻的一个GPU传来的梯度，在n-1个轮回后每个GPU得到了全部的梯度，最后每个GPU用相同梯度更新模型。但是ring方法每次都需要n-1轮传播才能更新梯度，虽然带宽问题解决了但是延迟太高。于是有tree方法，该方法将所有gpu之间的链接考虑，将传输速度更快的NVlink变成树结构，避免使用慢速的PCLE，这样降低了延迟。实际运用中这两种方法是混用的，因为一般gpu中都是NVlink带宽很高，所以用ring来吃满带宽，但是通过网络的地方（节点间）延迟很高，使用tree降低延迟。NCCL会自动完成这些分类。  
这里面关于学习率的调整有一个重要的公式linear scaling rule：new_lr = base_lr × k，即当global batch增大k倍时，学习率η也增大k倍。因为多卡上：g' = (1/(kB)) Σ grad，多除了一个k，所以梯度更新变慢了，为了弥补这个部分，需要把学习率调大k倍。但现实中不是完美成立，往往需要在开始几轮调大学习率。在通信过程中，GPU是闲置的，注意到反向传播是逐层进行的：Layer N → Layer N-1 → ... → Layer 1，所以每一层计算完就可以通信了，而不是等到全部计算完。NCCL将几个层分为一个bucket，Backward计算（第k层）←→ AllReduce（第k+1层）。最后就是DP最关键的问题，由于需要将整个模型放在每个GPU的显存中，但是很多大模型很难放进单个GPU中，ZeRO将模型切片，每个切片都包含了完整模型的一部分优化器，一部分梯度传导等（这也是为什么它不是MP方法）放进GPU中，所有GPU拼起来才是完整模型，而不是冗余地复制。动态AllGather：要使用梯度时就拼接，用完立刻释放。  
MP中有很多小类，比如TP（Tensor Parallelism）,PP（Pipeline Parallelism）,EP（Expert Parallelism / MoE）,Sequence Parallel。其中最核心的是TP。  
TP是最细粒度的模型并行，拆的是算子。有两种切割方式，Column Parallel（列切分）：这种切法不切开batch size，只切隐藏层，所以forward 无通信，backward 要 AllReduce，Row Parallel（行切分）：两个都切，这样forward就需要通信了，但是backward时由于计算的局部梯度，所以无需通信。TP每层中无论哪种方法都要进行小量的频繁通信，所以对延迟非常敏感。以transformer为例，TP主要在两个地方：QKAattention计算中，可以把head拆给不同的GPU，每个GPU计算自己的head，在FNN（假设为两层的MLP）$FFN(x) = \sigma ( x W_{1} ) W_{2}$ ,W1 Column Parallel，W2 Row Parallel。因为进入损失函数σ之前必须保留完整的数据，而row切会破坏数据的完整性，虽然可以通过ALLGETHER求和得到，但这样会多一次通信成本。  
PP不只是切模型，真正关键的在于实现调度（schedule）、流水化（pipeline）、气泡（bubble）、显存与通信的权衡。本质把模型按层切到不同 GPU 上，通过“微批次（micro-batch）”让前向和反向形成流水线，从而提高设备利用率。以transformer为例：Layer1 → Layer2 → Layer3 → Layer4，4 张GPU各分配一个layer。如果按照这个，那么总只有一个GPU在工作，micro-batch把一个 batch 拆成多个小块Batch = [b1, b2, b3, b4]，然后按时间流水线执行：  
{% highlight js linenos %}
{ 
t1: GPU0(b1)
t2: GPU0(b2), GPU1(b1)
t3: GPU0(b3), GPU1(b2), GPU2(b1)
t4: GPU0(b4), GPU1(b3), GPU2(b2), GPU3(b1)
...
}
{% endhighlight %}
在backward时也不是全部forward结束后求和再返回，而是采用1F1B（One Forward One Backward）交错进行。可见PP主要是一种调度方式而不是单独的并行，所以PP总和TP配合使用。  
EP是一种基于 MoE（Mixture-of-Experts）的模型并行方法，它通过把模型中的某一层（通常是 FFN）替换为多个“专家网络”，并将这些专家分布在不同 GPU 上，让不同输入动态选择部分专家进行计算。可以理解为稀疏注意力的路径选择版，他让一个token去某k（由Top-k机制决定，即去最高概率的k个）个专家（fnn）而不是所有的。选择专家的路由是一个线性层$p = \mathrm{softmax}(x W_{g})$，计算每个token去往专家的概率。而EP就是把专家分配在不同的GPU上，假设一个token在GPU0上，但是在GPU0上计算出他需要GPU1上的专家，那么就需要通信了。通信方式为All-to-All，每个 GPU 把自己的一部分数据发送给所有其他 GPU，同时从所有 GPU 接收数据。和AllReduce区别在于它不求和而是只做数据重分布（shuffle），让每个 GPU 得到不同数据。EP的难点在于负载均衡，假设某个专家接受了大量token而其他的专家闲置，会导致爆炸。Deepseek的优势就在于它把MoE做进了attention中，使得不同 token 用“不同的 attention 模块”。对比稀疏注意力，其选择的是每个token链接哪几个token。  

#### SFT（Supervised Fine-Tuning）
有监督微调,面对能力强大的 LLM，我们不再是在指定下游任务上构造有监督数据进行微调，而是选择训练模型的“通用指令遵循能力”，也就是一般通过**指令微调**的方式来进行SFT。所谓指令微调，即我们训练的输入是各种类型的用户指令，而需要模型拟合的输出则是我们希望模型在收到该指令后做出的回复。一般 SFT 所使用的指令数据集包括以下三个键：：  
{% highlight js linenos %}
{ 
    "instruction":"即输入的用户指令",
    "input":"执行该指令可能需要的补充输入，没有则置空",
    "output":"即模型应该给出的回复"
   又比如：
    "instruction":"将下列文本翻译成英文：",
    "input":"今天天气真好",
    "output":"Today is a nice day！"
}
{% endhighlight %}  
随着 LLM 能力的不断增强，模型的多轮对话能力逐渐受到重视。所谓多轮对话，是指模型在每一次对话时能够参考之前对话的历史记录来做出回复。模型是否支持多轮对话，与预训练是没有关系的。事实上，模型的多轮对话能力完全来自于 SFT 阶段。如果要使模型支持多轮对话，我们需要在 SFT 时将训练数据构造成多轮对话格式，让模型能够利用之前的知识来生成回答。构造多轮对话样本最优方式为直接要求模型预测每一轮对话的输出，也就是之前CLM是预测一个token，这里变成一轮对话。
#### RLHF (Reinforcement Learning from Human Feedback)
即人类反馈强化学习,事实上，从功能上出发，我们可以将LLM的训练过程分成预训练与对齐（alignment）两个阶段。预训练的核心作用是赋予模型海量的知识，而所谓对齐，其实就是让模型与人类价值观一致，从而输出人类希望其输出的内容。在这个过程中，SFT是让LLM和人类的指令对齐，从而具有指令遵循能力；而RLHF则是从更深层次令LLM和人类价值观对齐，令其达到安全、有用、无害的核心标准。本质是一种强化学习方法，强化学习关注智能体怎么在复杂、不确定的环境中最大化它能获得的奖励。主要由两部分构成：智能体和环境。在强化学习过程中，智能体会不断行动并从环境获取反馈，根据反馈来调整自己行动的策略。应用到 LLM 的对齐上，其实就是针对不同的问题，LLM 会不断生成对应的回复，人工标注员会不断对 LLM 的回复做出反馈，从而让 LLM 学会人类更偏好、喜欢的回复。  
RLHF 分为两个步骤：训练 RM 和 PPO 训练。
